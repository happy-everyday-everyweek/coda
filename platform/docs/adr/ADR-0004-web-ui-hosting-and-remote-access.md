# ADR-0004：Web UI 托管、本地访问与配对后的远程访问安全模型

- 状态：Accepted（文档决策已定；托管与远程链路实现为 UNVERIFIED / 依赖 BLOCKED）
- 日期：2026-11-07
- 对应任务：DOC-105
- 对应验收：WEB-001、WEB-002、LIFE-009、SEC-001、SEC-004、SYNC-002、SYNC-010、SYNC-014
- 关联文档：[ADR-0001](./ADR-0001-shared-core-runtime.md)、[ADR-0003](./ADR-0003-background-service-lifecycle.md)、`contracts/rpc.mjs`、[CONTRACT.md](../../CONTRACT.md)

## 背景

`SPEC.md` 12.4 要求：Web UI 由核心本地承载或作为已安装客户端连接核心，不依赖官方云网页；与 TUI/GUI 共用协议、能力与权限，不保存第二份权威任务数据库；浏览器刷新或关闭不影响 Agent 与终端；明文局域网 HTTP 不自动获得敏感管理权限，远程访问采用配对和加密连接。
`SPEC.md` 6.1 要求 Web UI 安装主要是本地资产 + 核心托管 + 访问配置，不意味着注册云账号；核心默认只为本机客户端提供**受认证**访问。
`SPEC.md` 11.3 与 14.4 要求局域网发现不等于信任、仅知道 IP 或配对页可访问不得获得管理权限；设备配对、Web 客户端、PA、外部 Agent 调用分别有可识别身份，且读取/控制/终端/文件/设备管理是可区分权限。
`CONTRACT.md` 第 8 节规定入口为 `clients/web/server.mjs`，命令形如 `node clients/web/server.mjs --port 0`：`--port 0` 表示随机端口，即「不要假定固定端口」。

现状证据（2026-11-07 文件快照）：`clients/shared/` 已有只读投影、RPC 客户端与确定性 Mock Core，但 `clients/web/`、`clients/tui/` **不存在**，没有任何 Web 服务可启动、无端口可扫描；`sync/` 的配对与加密帧同样未实现。故 `WEB-001`、`WEB-002`、`LIFE-009` 均为 `UNVERIFIED`（无法执行），远程链路为 `BLOCKED`（依赖 SYNC-101/103）。

## 决策

### 1. 托管形态

1. Web UI 是**薄客户端**：静态资产（HTML/JS/CSS）由本机进程托管，界面通过同一 JSON-RPC v1 契约（`contracts/rpc.mjs`）读投影、发命令，不直接访问核心数据库（CONTRACT 第 1 节、SPEC 12.4）。
2. 托管进程与核心进程分离：`clients/web/server.mjs` 只做「静态资产 + RPC 桥 + 认证门」，核心状态仍只由 `core/` 推进。Web 进程重启不影响 Agent 与终端（WEB-001）。
3. 默认绑定 `127.0.0.1`，端口 `0`（系统分配）。实际端点写入本机运行时描述文件（`<dataDir>/web.endpoint.json`，权限 0600），供本机客户端与诊断读取；**不得**默认绑定 `0.0.0.0`/`::`（LIFE-009）。
4. 静态资产随核心/Web 版本一起安装并做内容哈希；不使用第三方 CDN，不引入远程字体/脚本（否则违反「不依赖官方云」并扩大供应链面）。资产版本与核心版本不匹配时拒绝加载并提示升级（CORE-006）。
5. 浏览器只持有短时凭据，不持有设备长期身份私钥；刷新页面只需重新认证，不重建会话状态。

### 2. 本地访问（loopback）

1. loopback 访问仍需认证：服务启动时生成一次性会话令牌，写入 0600 的本机文件（或在浏览器打开时通过 URL fragment 传递一次并立即丢弃）。不提供「无 token 的 localhost 免认证」后门。
2. 该令牌绑定 `Host`/`Origin` 校验，防 DNS rebinding 与跨站请求；写操作要求 `Origin` 匹配本机端点或缺失（同源 fetch）。
3. 明文 HTTP 仅在 loopback 上允许；这是「不暴露到网络」的前提，不是「明文即安全」的结论。
4. 本机另一个用户若能读到令牌文件即视为已获得该用户权限——因此令牌文件权限、数据目录权限是安全边界的一部分（SEC-001）。

### 3. 远程访问（配对后）

1. 远程访问**必须先完成设备配对**（SYNC-101：二维码/短码/链接 + 设备指纹确认），配对产生独立设备身份与可撤销授权。
2. 传输使用端到端加密通道（X25519 密钥交换 + ChaCha20-Poly1305 AEAD 帧，见 SYNC-103 的设计约束）；Web 客户端只是「该设备上的一个客户端身份」，不因浏览器可达而自动成为可信设备。
3. 权限按动作区分并可单独授予/撤销：`read`（会话与消息）、`control`（发送/停止/审批）、`terminal`、`files`（附件与成果）、`admin`（设备与核心维护）。默认授予 `read` + `control`，其余需显式开启（SPEC 14.4）。
4. 明文局域网访问（未配对、仅 HTTP 可达）一律 `UNAUTHORIZED`：可以返回登录/配对入口页，但不得返回会话、审批、终端或文件内容（WEB-002）。
5. 不实现「IP 白名单即授权」「配对页可访问即信任」「记住设备即免认证」等捷径；发现不等于信任（SPEC 11.3）。
6. 撤销设备后：立即拒绝新连接与新命令，关闭该身份的活动订阅；**不改写**远端任务状态，也不能把远端运行中的回合显示为已停止（SYNC-010、SEC-004）。

### 4. 会话与订阅语义

1. `hello` 握手携带协议版本与客户端类型（`tui|gui|web|android`）；版本越界返回 `VERSION_MISMATCH`（`checkProtocolVersion`），不降级解析。
2. 订阅走「快照 + 有序事件」：`subscribe` 返回 `snapshot{seq}`，之后 `core.event` 严格 `seq + 1`；Web 刷新后用 `resume{fromSeq}` 续传，缺口由核心返回新快照（CONTRACT 第 2 节）。
3. 浏览器离线期间的状态如实显示：连接断开 → 顶部状态条显示「已断开，最后更新 <时间>」；不缓存「看起来在运行」的假状态，也不把离线当成功（SPEC 11.6、LIFE-005）。
4. 一个浏览器标签页 = 一个订阅者；多标签页各自独立 `seq` 游标，互不影响。

### 5. 安全边界汇总

| 场景 | 允许 | 禁止 |
|---|---|---|
| 本机浏览器（有令牌） | 全部只读 + 已授权控制 | 绕过核心直接改数据库 |
| 本机浏览器（无令牌） | 登录/配对入口页 | 任何会话/审批/终端/文件内容 |
| 局域网未配对（HTTP 可达） | 配对引导页 | 管理接口、会话数据、命令通道 |
| 已配对远程设备 | 授予的权限范围 | 超出 scope 的终端/文件/设备管理 |
| 已撤销设备 | 无 | 新连接、新命令、继续订阅 |

## 影响

- `WEB-101`、`WEB-102` 必须实现认证门与权限 scope；不能先做「能打开的页面」再补认证，否则会形成默认开放的管理面。
- 依赖 `SYNC-101`（配对）、`SYNC-103`（加密帧）、`SEC-103`（权限撤销）。这三项目前无实现文件，远程访问能力整体 `BLOCKED`。
- Web 端不得成为第二个「权威状态」：草稿、滚动位置、标签布局属客户端本地，不同步（SPEC 12.5、UI-007）。
- 诊断导出不得包含 Web 令牌、配对码与设备私钥（SEC-001、SEC-006）。
- 若未来加入官方中继，只转发端到端加密数据，中继侧不可读明文（SEC-007）；本 ADR 不引入中继为硬依赖。

## 备选方案

1. **绑定 `0.0.0.0` + Basic Auth**：部署简单，但把管理面暴露在明文 HTTP 上，且密码重放/CSRF 风险高，直接违反 SPEC 12.4 与 WEB-002；放弃。
2. **官方云托管 Web UI**：与 SPEC 2.4「不将 Web UI 设计成必须依赖官方云网站」冲突；放弃。
3. **仅本机、不做远程**：能满足 WEB-001 但放弃 SPEC 11.3 要求的远程访问与 Coda 双向控制场景；不采纳（远程作为可选增强，但安全模型必须先定）。
4. **localhost 免认证**：实现省事，但任何能访问 loopback 的本机进程/网页都可能拿到权限，违反「受认证访问」（SPEC 6.1、LIFE-009）；放弃。
