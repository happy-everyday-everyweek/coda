## 3. 首版风险提示：高度自主 PA（首启文案草案）

> 本节文案用于 `PA-105` 的首启确认；定稿前需产品与法务复核。风险披露必须**不能**被「实验性」字样替代（SPEC 14.2）。

### 3.1 首启弹窗正文（草案）

```text
关于「Coda 个人助理（PA）」的高度自主模式

启用后，PA 会代表你持续跟进工作，并可以在你已授权的设备上：
• 自主选择 Agent、创建会话、发送任务、跟进结果；
• 自动处理命令执行与文件修改的审批（包括子 Agent 发起的请求）；
• 通过 Agent 安装依赖、修改文件、执行命令，或进行其他该 Agent 支持的操作；
• 在已配对的设备之间发起远程操作。

这意味着：
• 这些操作可能修改你的文件、消耗模型额度，或产生你未逐条确认的副作用；
• 首版不提供额外的「自主程度」档位，也不提供专门的「一键暂停 PA」开关；
• 你可以随时停止某个 Agent 回合、停止核心服务，或撤销某台设备的授权——这几个动作含义不同，
  停止回合不会撤销已经产生的文件/命令副作用。

每次自主决定都会记录：时间、发起设备、目标、参数摘要、结果与决定者（PA 或你）。
你可以在「行动记录」中查看与导出。

继续即表示你理解并同意以上风险。

[ 取消 ]            [ 我已了解，启用高度自主模式 ]
```

### 3.2 文案约束

1. 必须出现「可能修改文件 / 执行命令 / 自动审批 / 跨设备操作」四项具体后果，不能只写「存在风险」。
2. 必须说明「无自主程度切换、无 PA 暂停开关」，避免用户以为存在安全阀（PA-007）。
3. 必须说明「停止回合 ≠ 撤销副作用」，与 `SPEC.md` 8.3 第 4 条一致。
4. 不得使用「AI 会替你负责」「完全可控」等表述。
5. 同意记录本身要进审计日志（时间、文案版本、用户确认），否则 `PA-006` 不成立。

## 4. 升级与回滚

### 4.1 升级前

1. 升级只支持「同主版本内向前」：`0.1.x → 0.2.0` 允许，降级需回滚流程（第 4.3 节）。
2. 升级前核心检查活跃回合、终端与传输任务；有活动时默认等待安全点，用户显式选择「立即升级」会被提示「运行中的任务将标记为中断」（ADR-0003 第 4 节）。
3. 升级前自动备份数据库（`db/backup-<schemaVersion>-<ts>.sqlite`）。

### 4.2 数据兼容

1. schema 迁移失败 → 核心**不启动写入**，保留旧库并输出可回退路径（`REL-004`）。
2. PA 消息与 Agent 会话为只追加数据，升级不得删除或重写历史；`schemaVersion` 随消息持久化。
3. 已撤销设备的授权记录保留，不因升级恢复。

### 4.3 回滚步骤（草案；需 `QA-105` 验证后定稿）

```text
1. 停止核心服务（不是删除数据）。
2. 切换版本指针回上一版本目录（Windows/macOS: current.json；Linux: current 符号链接）。
3. 若新版本已写入不兼容数据：用升级前的 db/backup-*.sqlite 覆盖当前库；
   不接受「尽力降级」，宁可回滚到旧库也不要半迁移状态。
4. 启动旧版本核心，用 core.diagnostics 核对 schemaVersion 与事件序号连续性。
5. 通知各 UI 重启并重新握手；版本不匹配时按 PROTOCOL_VERSION 报 VERSION_MISMATCH。
6. 回滚记录（原因、版本、数据恢复点）写入诊断导出。
```

回滚**不**撤销：已发送给 Agent 的命令副作用、已产生的文件修改、已传输的成果、已消耗的模型额度。

### 4.4 卸载

1. 卸载 UI 不删核心与其他 UI（`LIFE-007`）。
2. 卸载核心前列出运行中回合与终端，默认保留数据，需明确确认才删除（`LIFE-008`）。
3. 「删除会话」「撤销设备」「停止核心」「停止某个 Agent 回合」是四个不同动作，文案不得互换（`SEC-008`）。
