## 1. 背景

`SPEC.md` v0.2 与当前实现切片出现 6 处需要显式记录的偏差/澄清。按 `README.md` 的变更规则（「任何范围缩减必须明确写进 SPEC 的版本记录」「若实现与规格冲突，先修订规格并评审」），这些偏差不能只体现在代码或 ADR 中，否则会形成未记录的产品行为（`DOC-004` 不成立）。

偏差来源分三类：

1. **技术选型偏差**（(a)）：SPEC 建议 Rust 核心，交付为 Node 24 参考实现。
2. **语义澄清**（(b)、(d)、(e)）：SPEC 原文允许多种实现，需要把已选方案固化为可验收的外部行为。
3. **文档内部不一致**（(c)、(f)）：CONTRACT 模块归属与实现不符、TODO 任务范围笔误。

Lead 已对 (a)–(f) 给出决策；本文档把它们整理为可评审、可粘贴的变更记录，同时单列仍待补的 `DOC-002` 缺口与 P1 延期名单问题（第 5 节）。

## 2. 变更点

### (a) 核心语言：Node 24 参考实现，外部行为不变

| 项 | 内容 |
|---|---|
| 现状 | `SPEC.md` 5.4 建议共享核心采用 Rust，并注明「最终核心语言可以在技术设计中确认，不改变本规格的外部行为」 |
| 决策 | 保留 Node.js 24 ESM 参考实现（零外部依赖），Rust 迁移列为后续技术债 |
| 依据 | [ADR-0001](./adr/ADR-0001-shared-core-runtime.md)；本机无 Rust 工具链；契约由 `platform/contracts/` 与契约测试固定 |

**提案文本（用于 SPEC 5.4 段末）**

```text
共享核心的参考实现采用 Node.js 24 ESM（零外部依赖，使用内置 node:sqlite /
node:crypto / node:test）。核心语言属于实现细节，不改变本文规定的外部行为：
协议、事件、命令状态机与能力声明由 contracts/ 与契约测试固定。未来迁移到 Rust
只替换 platform/core/ 的实现，contracts/ 与客户端契约保持不变；该迁移不构成范围变更。
```

**影响**：`PERF-001`/`PERF-004` 的基准必须在 Node 实测值上判定，不得引用 Rust 的预期性能；`QA-007` 需覆盖 Node 运行时许可（MIT，已在 `LICENSE-AUDIT.md` §2.3 登记）；GUI 仍按 SPEC 5.4 走 Rust + GPUI，不受本项影响。

### (b) PA 以 HLC 作为逻辑时间与等效游标

| 项 | 内容 |
|---|---|
| 现状 | SPEC 10.4 只要求「逻辑时间信息」；11.1 列举「版本向量/等效游标」，未指定具体机制 |
| 决策 | 采用混合逻辑时钟（HLC），字符串格式 `物理毫秒(15 位):计数器(6 位):节点ID` |
| 依据 | [ADR-0002](./adr/ADR-0002-pa-single-session-and-sync.md) 第 2 节；实现 `pa/schema.mjs` 的 `createHybridClock` / `comparePaMessages` |

**提案文本（用于 SPEC 10.4 段末，并在 11.1 追加一句）**

```text
PA 消息的逻辑时间采用混合逻辑时钟（HLC），格式为「物理毫秒:计数器:节点ID」。
全局顺序为（物理毫秒、计数器、节点ID、消息ID）的码点序比较，结果与到达顺序、
本机时钟和系统区域设置无关；墙钟时间只用于展示，不作为排序依据。
HLC 即第 11.1 节所述的「等效游标」：同步游标取已见消息的最大 HLC。
```

**影响**：`PA-009`、`SYNC-009`、`SYNC-013` 的判定以此顺序为唯一标准；同 `id` 内容分叉按规范化 JSON 取较小者并报告冲突（不静默丢消息）；`sync/` 实现必须复用同一比较函数，不得自行实现排序。

### (c) `normalizeWorkspacePath` 归属：`core/workspace.mjs` 为准

| 项 | 内容 |
|---|---|
| 现状 | `CONTRACT.md` §8 把 `normalizeWorkspacePath` 列为 `security/index.mjs` 的导出，实现位于 `core/workspace.mjs` |
| 决策 | 以 `core/workspace.mjs` 为唯一实现；`security/index.mjs` 只做 re-export；由 Lead 修改 `CONTRACT.md` §8 |
| 依据 | 路径规范化与工作区包含性校验同源（`isPathInside` / `resolveInsideWorkspace`），拆到 `security/` 会造成两处实现 |

**提案文本（用于 SPEC 9.3 或 CONTRACT §8 变更说明）**

```text
工作区路径规范化与包含关系校验由核心的工作区模块单点实现（core/workspace.mjs），
安全模块只做再导出，不重复实现路径规则。所有模块（含同步与远程文件访问）
必须调用同一实现，不得各自拼接或比较路径字符串。
```

**影响**：本项属 `CONTRACT.md` 修订，**不改 SPEC 正文语义**；`SEC-002`、`WORK-002` 的验收以单点实现为准；`platform/README.md` 的模块表已按此现状描述。

### (d) Web UI：loopback 也需一次性令牌

| 项 | 内容 |
|---|---|
| 现状 | SPEC 12.4 只要求「明文局域网 HTTP 不自动获得敏感管理权限」「远程访问采用配对和加密连接」；未要求本机访问也认证 |
| 决策 | 本机（loopback）访问仍需一次性会话令牌，令牌写入权限 0600 的本机文件或经 URL fragment 一次性传递；校验 `Origin`/`Host`；不提供 localhost 免认证后门 |
| 依据 | [ADR-0004](./adr/ADR-0004-web-ui-hosting-and-remote-access.md) 第 2 节；`LIFE-009` 的「受认证访问」在 SPEC 6.1 已有铺垫 |

**提案文本（用于 SPEC 12.4 追加）**

```text
Web UI 默认绑定 127.0.0.1 并由系统分配端口。即使在本机访问，也必须使用一次性
会话令牌完成认证；令牌保存在仅当前用户可读（0600）的本机文件中，或通过一次性
链接片段传递一次。服务端校验 Host 与 Origin，拒绝跨站请求。不允许「localhost
免认证」的例外：能访问 loopback 的进程或网页不等于已获得管理权限。
```

**验收补充（供 Lead 写入 ACCEPTANCE，不改现有 ID 编号）**

```text
LIFE-009 补充判定：
Given Web UI 已安装且未配对；When 从本机浏览器访问且不带令牌；
Then 只返回登录/配对入口，不返回任何会话、审批、终端或文件内容；
并且服务默认仅绑定 127.0.0.1，不对局域网地址监听。

WEB-002 补充判定：
Given 同一台机器上有另一个本机进程或网页尝试访问 Web 端点；
When 其未持有一次性令牌或 Origin 不匹配；
Then 请求被拒绝（UNAUTHORIZED），且不产生任何读取或控制副作用。
```

**影响**：`WEB-101`、`WEB-102` 必须实现认证门后再做功能；`LIFE-009`/`WEB-002` 从「不默认开放」升级为「本机也需认证」；首启 UX 增加「一次性链接」环节，需在发布说明的已知限制中说明令牌文件即本机信任边界（`LIM-40`）。

### (e) 核心最低运行时：Node 24

| 项 | 内容 |

| 决策 | `engines` 改为 `>=24`；安装器需检测版本并给出修复命令 |
| 依据 | [ADR-0001](./adr/ADR-0001-shared-core-runtime.md) 第 2 节；`LICENSE-AUDIT.md` §2.2 |

**提案文本（用于 SPEC 6.1 安装前提）**

```text
共享核心要求 Node.js 24 或更高版本（使用内置 SQLite）。安装器必须在安装前
检测运行时版本；不满足时中止安装并给出可执行的修复命令，不得静默降级到
需要实验开关的旧版本，也不得回退到外部数据库驱动。
```

**影响**：`LIFE-001`（只装 TUI 自动装核心）需增加版本检测步骤；`QA-001` 的安装包需写明运行时依赖；`README.md` 的运行前提已注明 22+ 与 `node:sqlite` 的关系，`engines` 修正后应同步改为 24+。
