本文中的验收 ID 是稳定标识。任务、PR、测试报告和能力矩阵应引用这些 ID，而不是只写“已完成”“功能可用”。

## 1. 验收规则

### 1.1 结果状态

| 状态 | 含义 | 是否计入发布 |
|---|---|---|
| PASS | 所有前置条件、步骤和预期均满足，证据可复现 | 是 |
| CONDITIONAL PASS | 仅适用于上游明确不具备且产品已声明降级的非必需能力；基础门禁不可使用 | 仅限已批准降级项 |
| FAIL | 实际结果与预期不符 | 否 |
| BLOCKED | 依赖未安装、接口未知、上游缺陷、环境不可用 | 否 |
| NOT RUN | 尚未执行 | 否 |
| N/A | 该 Agent 明确不具备此可选能力，且能力矩阵已声明 | 不计为通过，不得掩盖基础门禁 |

`BLOCKED`、`NOT RUN` 和普通 `N/A` 都不能作为首版完成依据。某个 Agent 的核心创建、发送、流式、停止、恢复任一项为 BLOCKED，则该 Agent 不得标记为“首版已支持”，且必须列入发布阻塞项。

### 1.2 优先级和门槛

- **P0**：发布硬门槛。未通过不得发布对应平台或声称该 Agent 已支持。
- **P1**：应在首版完成；除非有规格变更记录和明确延期说明，否则同样阻塞发布。
- **P2**：后续增强，不阻塞首版。

每个 Agent 的基础门禁对首版名单均是 P0。可选能力只有在适配器声明支持时才需通过对应测试；声明后失败即为 P0。

### 1.3 证据要求

每次验收必须记录：

```text
run_id:
commit:
product_version:
date:
executor:
OS / version / architecture:
device / CPU / RAM:
Agent name / version / install path:
execution environment: host | WSL:<distro> | Android
network topology:
test data seed:
result: PASS | FAIL | BLOCKED | NOT RUN
commands and logs:
screenshots/video (manual only evidence supplement):
spec / acceptance references:
```

保存到 `artifacts/acceptance/<run_id>/`，测试日志不得包含真实 Token、密钥、用户私有文件内容。自动化测试必须有可搜索的验收 ID 或测试标签，例如 `AGT-003`。

### 1.4 基准环境

除非条目另有说明，性能和跨平台验收采用以下基准：

- Windows 11 x86_64 + WSL2 Ubuntu 24.04，4 核 / 8 GiB RAM / SSD。
- macOS 14+ Apple Silicon，8 GiB RAM 以上。
- Linux Ubuntu 24.04 x86_64，4 核 / 8 GiB RAM / SSD；如发布 arm64，需对应实机或 CI。
- Android 真机 arm64，系统版本覆盖 Coda 当前支持范围中的至少两个主版本。
- 局域网：有线或 5 GHz Wi-Fi，设备间 RTT < 50 ms，无统一公网中继。
- Agent 版本固定到支持矩阵中的版本；不得在验收记录中只写“最新版”。

## 2. 发布门槛

| Gate | 内容 | 必须通过 |
|---|---|---|
| G0 | 规格、验收、待办和变更记录齐全 | DOC-001 ~ DOC-004 |
| G1 | 共享核心、三界面安装共存、三平台后台运行 | LIFE、PLAT、UI 全部 P0 |
| G2 | 参考适配器、完整能力模型、WSL | WSL、ADP-001~019、Claude Code、Codex |
| G3 | 全部首版 Agent 能力矩阵和真实接口冒烟 | 所有首版名单的 ADP 基础门禁与声明的专项能力 |
| G4 | PA 单会话、局域网分布式同步、双向 Coda 控制 | PA、SYNC、Coda 节点全部 P0 |
| G5 | 成果交接、安全、可靠性、性能、打包发布 | ART、SEC、REL、PERF、QA 全部 P0 |

G3 不是“只要接上任何一个 Agent 即可”。首版名单中任何一项无证据、仅模型 API 接入或仅能启动终端，都不能通过 G3。

## 7. Agent 适配通用门禁

以下门禁适用于第 8 节所有首版名单中的 Agent。测试必须使用对应真实可执行程序与固定版本，不能只用 Mock。

| ID | 优先级 | Given / When / Then | 证据 |
|---|---|---|---|
| ADP-001 | P0 | 发现 Agent 时只做不引发登录、MCP、Hooks 或会话创建的健康探测；未知状态明确显示未知 | 进程、网络、日志 |
| ADP-002 | P0 | 多账号实例的凭据、会话、模型目录相互隔离；未配置的 ambient credentials 不会被静默继承 | 账号隔离测试 |

| ADP-004 | P0 | 能持久化供应方会话引用并在应用重启后恢复本产品创建的会话；恢复失败可见且不伪装 | 重启测试 |
| ADP-005 | P0 | 在回合运行中执行停止，最终状态来自上游确认或可解释的进程终止；不能只改 UI | 停止前后事件 |

| ADP-014 | P0，按能力 | 子 Agent、后台命令或自主工作产生的事件按来源关联；父回合结束后不得丢弃仍在运行的子任务 | 生命周期回放 |

| ADP-018 | P0 | Agent 升级后重新探测版本与协议，不沿用旧缓存；不兼容时阻止使用并给出支持版本 | 升级测试 |
| ADP-019 | P1 | 协议原始帧可输出有界、脱敏诊断；普通日志不含完整密钥、附件正文和全部工具输入 | 日志抽样 |

## 15. 最终发布判定

一个版本只有同时满足以下条件才可标记首版完成：

1. G0 到 G5 全部 PASS。
2. 首版 Agent 名单中每个对象均为 `Supported`；任何 `Experimental` 或 `Unavailable` 都需有明确规格变更，不能隐藏在默认列表。
3. 三平台三界面均可安装、共存、后台常驻；关闭所有 UI 后任务与通知继续。
4. WSL 真实链路、Coda 双向控制和 PA 单会话均已通过端到端验收。
5. 局域网无中心服务、离线队列、重连收敛、命令去重和审批竞争均通过。
6. 没有任何 P0 项为 FAIL、BLOCKED 或 NOT RUN。
7. 已知限制、支持版本、风险和升级路径写入发布说明。
