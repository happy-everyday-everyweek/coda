## 1. Agent 执行规则

1. 认领前阅读对应规格与验收，确认依赖和最新 PR head；不得基于本文件初始 SHA 强行覆盖后续提交。
2. 任务分支/工作树必须最终回到 `feat/desktop-agent-platform`，不另建替代 PR。
3. 新领域功能落在 Rust 核心；Node 仅保留迁移参考、golden fixture 对照与明确的临时代理。
4. 先补契约/失败测试，再实现；提交必须列验收 ID、证据路径、已知限制与回滚方式。
5. 不得把源码存在、单测存在、CI 绿、mock 网关或 fake transport 标为真实发布 PASS。
6. 不把密钥/个人数据写入 fixtures；真实服务验收使用用户提供的专用测试账户或明确授权环境，日志脱敏。
7. 任何商业、接口、设备或环境阻塞保持发布阻塞；需要降范围时先请用户修改 SPEC-S2。

## 14. 当前最高优先级执行切片

在用户没有另行调整顺序时，推荐下一批开发 Agent 按以下顺序认领：

1. **S2-0001~0005**：审查/范围/状态模型和证据规范。
2. **S2-0101~0106**：先消除三套 PA 与命令/游标语义，跨语言 fixtures。
3. **S2-0201~0204**：Rust 核心最小可对照骨架、单写权威与 RPC。
4. **S2-0401**：Android 持久命令收据，优先消除重复副作用风险。
5. **S2-0301/0304**：三平台后台与 GPUI 产品壳。
6. **S2-0402~0407**：正式加密节点与真机。
7. **S2-05→S2-06→S2-07**：跨端 PA→目标/接管→记忆。

每条切片必须提交可运行测试与证据；若环境不可用，只能保持阻塞并记录下一步，不得将验收改成“静态完成”。
