## 1. 阶段目标与范围

第二阶段同时推进：

1. **第一阶段产品化收口**：三平台安装与后台、WSL、GPUI 产品界面、Android 真机、可靠恢复和真实 Agent 验收。
2. **跨端连续性**：可信配对、加密、PA 单会话、可靠命令、离线同步、成果交接。
3. **PA 深化**：多目标、初始目标对齐、目标内自主边界、长期记忆、全局人工接管。
4. **核心迁移**：Node 24 参考核心迁移到 Rust；GUI 保持 Rust + GPUI。
5. **环境与维护扩展**：SSH、容器、可选统一配置、有限 Agent 安装/升级/修复/卸载。
6. **全量真实 Agent 验收**：首版名单全部达到真实服务、真实工具循环和声明能力验收；不得以商业门槛或缺少本地接口静默标记完成。

所有范围均为第二阶段目标，不因“任务很多”默认降级为后续。任何延期必须经用户明确批准并修改本文件与版本记录。

## 2. 第二阶段不变的约束

- 桌面核心不开发另一套通用 Coding Agent；已有 Agent 与 Coda Coding Agent 由适配器管理。
- PA 保持独立、连续的单用户单会话；不按目标、设备或 Agent 建立第二条 PA 会话。
- PA 对话不做 Agent 任务卡片关联，不复制 Agent 工具过程；用户可绕过 PA 直接管理 Agent。
- 不做原 Agent 会话跨设备迁移或原样续跑；远程控制与按需成果交接不等于迁移。
- 不做全工作区持续双向同步；文件/成果按需交接。
- 无强制中心同步服务，局域网优先；无可信中继时，设备不再同时在线就无法保证送达。
- 不用 mock 模型网关、fake ACP、loopback 或内存 transport 冒充真实服务/真机验收。
- 配置中心不默认接管 Agent 原生配置；安装维护不接管无法确认所有权的安装。

## 3. 第二阶段新增和替代的产品决策

### 3.1 替代：自主边界与人工接管

第一阶段“高度自主、无额外自主控制”的规则在第二阶段升级为：

1. 默认仍是高度自主，但每个目标可以在对齐时设置**更严格**的行动和审批边界。
2. PA 可以在与用户的明确目标对齐对话中修改目标边界；普通任务对话不得静默扩大权限。
3. 目标可以暂停，暂停只阻止该目标相关的新行动，不停止 PA 普通聊天，也不自动杀死正在运行的 Agent；已运行行动必须逐一显示状态并提供人工停止。
4. 新增**全局人工接管**：立即禁止 PA 发起新的自主行动和自动审批，保留用户直接聊天与直接控制 Agent 的能力。
5. 人工接管不伪造已停止：已排队但目标未收到的命令标记为取消/暂停；已送达或已执行命令必须查询真实状态；需要停止的任务由用户明确选择。
6. 解除人工接管、恢复目标和扩大边界需用户显式确认，并写审计。
7. 人工接管本身跨端同步；离线时本端立即生效，其他端未收到前不得显示全局已同步。

### 3.2 新增：目标系统

1. PA 创建时自动生成一个初始目标，并进入边界对齐。
2. 一个 PA 可有多个目标；目标与 PA 单会话并存，不是新聊天线程，不是 Todo，也不是 Agent 会话。
3. 每个目标包含：目标 ID、标题、意图/成功标准、范围、允许的 Agent/设备/工作区、行动边界、审批边界、主动跟进策略、状态、版本和确认记录。
4. 状态：`draft | aligning | active | paused | completed | archived`；完成/归档不删除历史。
5. 目标更新生成新版本；正在执行的任务保留启动时的目标版本，后续行动使用最新已确认版本。
6. PA 可建议目标拆分、Agent 选择和跟进，但不得借目标对齐扩大设备、文件、凭据或高风险权限。
7. 目标结果与 Agent 会话可在内部引用，但不要求在 PA 会话显示卡片或集中任务面板。

### 3.3 新增：长期记忆系统

记忆是 PA 的可管理个人上下文，不是完整聊天日志的别名，不是向所有 Agent 公开的数据库。

#### 记忆类别

| 类别 | 示例 | 默认生命周期 |
|---|---|---|
| profile | 用户称呼、语言与稳定偏好 | 长期，用户可改 |
| preference | 工作方式、通知与互动偏好 | 长期，随显式偏好更新 |
| fact | 用户明确提供的长期事实 | 长期，支持过期/失效 |
| goal_context | 目标对齐产生的边界和背景 | 跟随目标版本与状态 |
| episode | 已完成经验的摘要 | 可保留，需来源与置信度 |
| sensitive | 用户明确允许保存的敏感个人上下文 | 默认不自动提取，单独授权 |

密码、API Key、OAuth Token、配对私钥、完整凭据文件不得进入记忆正文或记忆嵌入。

#### 写入与更新

1. 支持用户显式记忆、用户确认的建议记忆，以及政策允许的自动提炼。
2. 自动提炼不得把一次任务指令、临时路径、密钥、第三方机密或不确定猜测保存为长期事实。
3. 每条记忆含 `memory_id`、类别、正文/结构化值、来源消息或目标、创建节点、创建/更新时间、置信度、有效期、敏感级别、版本和状态。
4. 冲突记忆不静默覆盖：保留来源和版本，标记冲突；影响行为前由用户确认或按明确规则解决。
5. 支持查看、搜索、修改、固定、禁用、删除、按目标/类别清理和导出。
6. 删除与禁用同步到所有节点；模型检索必须尊重删除/禁用，不继续把旧副本作为上下文。

#### 检索与使用

1. PA 按当前对话、目标和用户偏好检索必要记忆，不默认把全部记忆注入模型。
2. 模型可见内容必须可解释：用户能查看“本次使用了哪些记忆及原因”。
3. 无记忆可用时正常对话，不阻塞本机独立运行。
4. Agent 默认不能读取 PA 记忆；确需传递时由 PA 生成最小任务上下文，并留下审计。
5. 记忆可用于规划/回复模型，但规划模型与回复模型的供应商不同步时，敏感记忆的出境范围需符合用户授权。

#### 同步与隐私

1. 非敏感记忆与 PA 单会话跨端同步，使用全局 ID、版本、来源与确定性冲突处理。
2. 敏感记忆默认可选择仅本机；同步需显式启用并端到端加密。
3. 嵌入向量可作为派生数据本地重建，不要求跨端同步；原始记忆与删除墓碑必须同步。
4. 密钥和秘密不以“敏感记忆”的形式绕过既有的凭据不同步规则。
5. 提供按目标、类别、来源和时间删除的批量控制；删除派生索引与模型上下文引用。

#### 性能与降级

1. 首版不强制向量数据库或重型本地模型；可采用本地结构化存储 + 关键词/混合检索。
2. 记忆检索失败时 PA 显示降级并可继续对话，不把记忆不可用误报成用户没有记忆。
3. 自动提炼在后台执行，不能阻塞消息发送；重复运行不生成重复记忆。

### 3.4 Rust 核心迁移

1. 目标形态：Rust 共享核心 + Rust/GPUI GUI + TUI + Web 薄客户端；Android 通过版本化 RPC 与同步协议接入。
2. Node 24 当前实现作为**行为参考与迁移对照**，不是最终长期核心。
3. 迁移期间只允许一个写入权威：某用户数据目录要么由 Node 服务，要么由 Rust 服务，禁止并行双写。
4. 先冻结协议/schema/fixture，再逐模块替换；未迁移模块可通过明确的临时边界调用参考实现，但必须记录迁移状态。
5. 同一组 golden fixtures 在 Node 与 Rust 产生相同领域事件、错误、命令收据、PA 合并与冲突结果。
6. 数据库优先通过导出/导入或严格迁移进入 Rust，禁止直接假设两个实现的 SQLite 写路径可同时使用。
7. 切换前备份、dry-run、校验计数与哈希；切换失败可回到旧版本，未确认副作用保持 `unknown`。
8. 迁移完成后安装包不再要求用户安装 Node；GUI 与核心仍保持独立进程，关闭 UI 不停止核心。

## 4. 产品化与跨端连续性的强制要求

### 4.1 生命周期与命令

- 三平台用户级后台、单实例、登录启动、崩溃退避和可回滚升级必须实测。
- 所有会改变 Agent/设备状态的命令在外部 I/O 前持久化；Android 不得继续使用纯内存 LRU 收据。
- 副作用后崩溃先核对上游；不能确定则为 `unknown`，禁止盲重试。
- 进程/系统休眠、关机、Android 被杀必须显示中断/未知，不能显示继续运行。

### 4.2 可信设备与加密

- Android 明文 TCP + 对称 token 是过渡实现；第二阶段正式路径必须升级到长期设备身份、端到端加密、人工指纹确认和按设备撤销。
- 私钥进入 Android Keystore/StrongBox（可用时）和桌面 OS 安全存储。
- 读取、控制、审批、终端、文件、设备/核心维护分别授权；多客户端限流与撤销后关闭订阅。
- LAN 无公网、无中心服务下可配对、同步与控制；未配对/撤销/越权/重放必须拒绝。

### 4.3 PA 单会话与同步契约

- `pa/schema`、`core/domain`、`sync` 的三套 PA 字段和 HLC/Lamport/wall clock 排序必须统一为单一 canonical contract。
- Android、Rust core、Web/TUI/GPUI 均使用同一 ID、消息结构、游标和错误语义。
- 双端同时发送、乱序、重复、延迟、网络分区和双方离线后最终一致。
- PA 与 Agent 的工具过程分离；自主操作只通过统一命令层，写审计并使用幂等 ID。

### 4.4 Agent 真实验收

- 首版名单全部进行真实服务、真实工具循环、停止、恢复、审批/提问（若声明）、错误与配额验收。
- 每个 Agent 固定版本与执行环境；mock 网关证据只作为协议路径补充。
- TRAE 商业套餐、WorkBuddy 无本地接口等属于明确发布阻塞：必须获得可验证官方入口和真实账户，或经用户批准修改产品范围；不得用 `BLOCKED` 算完成。
- 不接受截图 OCR/键鼠 UI 自动化作为完整支持的默认主链路。

## 5. 环境与维护扩展

### 5.1 WSL / SSH / 容器

- WSL 为第一阶段继承的必做项，路径、凭据、Git、终端、Agent 与成果均归属指定发行版。
- SSH：远端核心/Agent/工作区留在远端，不以本地同名目录或凭据代替；支持重连与主机身份校验。
- 容器：明确镜像、容器 ID、挂载、生命周期、网络和资源限制；不得把容器内路径当宿主机授权。
- 三者均不迁移会话宿主，不做工作区镜像。

### 5.2 可选统一配置

- 用户显式开启，先扫描和预览，不默认写入。
- 支持配置/MCP/Skills/权限规则的映射、差异、验证、备份、回滚、来源追踪和冲突提示。
- 第三方不支持的字段不伪造统一；原生设置与托管设置必须可区分。
- 凭据和敏感配置不进入普通配置同步。

### 5.3 Agent 安装维护

- 只对可验证安装来源、真实路径、包管理器所有权和版本的对象提供自动安装/升级/修复/卸载。
- 活跃进程持有租约，不能替换运行中二进制；需要中断时明确确认。
- 无法确认所有权时只给手工指引，不猜测包管理器。
- 安装包校验、回滚、失败诊断与卸载数据保护纳入验收。

## 7. 迁移和实施顺序

1. **S2-A**：固定 PR #13 基线，审查问题闭环；冻结 canonical contracts，补真实验收证据规则。
2. **S2-B**：Rust core 骨架与 golden fixtures，迁移数据库/命令/会话/PA；Node 只作对照。
3. **S2-C**：三平台后台、安装共存、升级/回滚、WSL 与 GPUI 产品化。
4. **S2-D**：设备身份/加密/Android 真机、可靠命令、PA 单会话与成果同步。
5. **S2-E**：目标、自主边界、人工接管与长期记忆。
6. **S2-F**：SSH、容器、配置中心和 Agent 维护。
7. **S2-G**：全部 Agent 真实服务回归、三平台/真机 E2E、性能、许可和发布候选。

可以并行开发，但 D/E 依赖 canonical contracts 与可靠命令；任何迁移到 Rust 后的新功能不得重新只在 Node 核心实现。
