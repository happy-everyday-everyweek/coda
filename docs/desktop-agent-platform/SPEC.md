## 0. 文档约定

本文使用以下约束词：

- **必须**：首版验收的强制要求。
- **应该**：原则上应实现；若受上游限制，必须有明确的降级行为与说明。
- **可以**：可选增强，不应阻塞核心链路。
- **后续**：不纳入首版交付，但架构不得将其永久排除。

“首版适配某 Agent”不是指所有 Agent 具有完全相同的原生按钮，而是指：基础控制链路可用、公开能力矩阵真实、已声明能力通过测试、缺失能力有合理适配或明确降级。

## 1. 背景与现状

### 1.1 Coda 已有基础

根据对 `happy-everyday-everyweek/coda` 当前 `dev` 分支及 Personal Agent 合并前实现的阅读，Coda 已具备以下与本项目有关的基础：

1. Android 上自包含的 Coding Agent 运行环境，包含 ZCode、Linux 用户空间、工作区、文件、Git 和终端。
2. `zcode app-server --stdio` 核心进程，宿主通过 NDJSON / JSON-RPC 风格协议与其通信。
3. 多会话、流式消息、工具调用、权限请求、用户提问、子 Agent、工作流和定时任务等控制经验。
4. 模型供应商、OAuth 网关和 WorkBuddy / CodeBuddy 独立网关等接入经验。
5. 通过本机 MCP 暴露手机控制能力的实践。
6. 已合并到 `dev` 的 Personal Agent：采用独立的 MaiBot Lite 内核，独立于 Coding Agent 的资料、会话和配置，面向单用户、单会话；可协调 Coding Agent、接收完成事件、处理审批、切换模型及读取有限上下文。
7. Coda 的 Qoder、TRAE、Cursor、CodeBuddy 等已有代码中包含模型/OAuth 渠道接入能力。此类能力可以为账号和模型接入提供经验，但**不等于已经完成这些产品的原生 Agent 会话适配**。

### 1.2 为什么不是简单移植 Coda

Coda 是 Android 上自带 Coding Agent 执行能力的 Agent 工具。新桌面端的主要责任是管理电脑上已有的 Agent，不重复实现一套通用 Coding Agent 内核。两者的形态不同，但可通过统一节点、协议和 Personal Agent 深度协同。

## 2. 产品定位与边界

### 2.1 一句话定位

> 一个以本地设备为执行主体、以共享核心统一管理已有 Agent、以独立 Personal Agent 提供个人协助与主动跟进的跨端 Agent 控制与协同平台。

### 2.2 产品由四类对象组成

1. **共享核心**：常驻后台，管理 Agent、会话、工作区、终端、文件成果、通知、设备连接和同步。
2. **三种界面**：TUI、GUI、Web UI，均是共享核心的客户端，不是三个独立产品。
3. **已有 Agent 适配器**：把 Claude Code、Codex 等已有 Agent 的协议与生命周期映射到统一领域模型。
4. **Personal Agent（PA）**：独立、连续的单会话个人助理，负责交流、协调和主动跟进，不是通用 Coding Agent 的替代品。

### 2.3 Coda 与桌面端的分工

| 对象 | 主要定位 | 自有执行能力 |
|---|---|---|
| Android Coda | 移动 Agent 工具与移动执行节点 | 保留现有 Coda Coding Agent、Linux 环境、手机控制等能力 |
| 桌面共享核心 | 管理电脑上已有 Agent 的控制面 | 不新造通用 Coding Agent；负责适配、编排、状态和同步 |
| Personal Agent | 跨端个人助理 | 独立于 Coding Agent，可调用受控协调能力 |
| TUI / GUI / Web UI | 查看与操作 | 不直接拥有 Agent 进程或独立任务状态 |

### 2.4 明确不做的事情

首版不得把产品扩张为以下形态：

- 不再开发另一套用于替代 Claude Code、Codex 等的通用 Coding Agent。
- 不统一导入、收纳第三方 Agent 的全部历史会话。
- 不默认接管第三方 Agent 的账号、模型、MCP、Skills 或权限配置。
- 不承诺原会话及其完整执行状态跨设备迁移、原样续跑。
- 不做工作区或指定文件夹的持续双向同步，不成为同步盘。
- 不要求用户部署同步服务器，也不以官方中心服务作为局域网协同的前提。
- 不将 Web UI 设计成必须依赖官方云网站的另一套产品。
- 不要求本机完全无互联网时仍能调用云端模型；首版“离线独立”指另一端关机、休眠或断连时，本端仍可运行。
- 不纳入“目标”系统、目标初始化向导及目标驱动的自主程度对齐。
- 不提供额外的 PA 自主程度切换，也不提供专门的“一键暂停 PA 自主行动”开关；首版采用明确告知风险的高度自主试验模式。

## 3. 用户与核心场景

### 3.1 目标用户

- 在一台或多台电脑上同时使用多个 Coding Agent 的开发者。
- 希望在手机与电脑之间查看、操作和接续管理任务的单用户。
- 喜欢 GUI，也有一部分场景需要终端或浏览器访问的用户。
- 希望保留各 Agent 原有账号、订阅、工作区和使用习惯的用户。

首版以**单用户、多可信设备**为主要模型，不以团队权限、组织协作或多人共同编辑为目标。

### 3.2 必须覆盖的用户旅程

1. 用户只安装 TUI，安装器自动安装共享核心；之后安装 GUI，直接复用已有核心、数据与后台任务。
2. 用户在 GUI 中启动 Agent 会话，关闭 GUI 后任务继续；再用 TUI 或 Web UI 打开同一会话，看到相同状态。
3. 用户在 Windows 上选择 WSL 发行版、Linux 工作区和 Agent，创建并恢复会话。
4. 用户在 Coda 手机上向电脑中的 Agent 发送指令、处理审批、查看状态和取得成果。
5. 用户在电脑上调用 Coda 节点已有的执行能力，实现双向调度。
6. 用户直接使用某个 Agent，不经过 PA；也可以让 PA 在后台协助协调与跟进。
7. 用户在电脑离线时继续与手机 PA 对话并操作手机本机 Agent；电脑侧显示为离线最后已知状态。
8. 用户对不支持原生插话的 Agent 发送追加指令，核心通过停止当前回合、恢复原会话并发送新指令完成适配。
9. 用户按需把附件交给 Agent，或把补丁、截图和生成物下载到另一设备，而不同步整个工作区。

## 4. 首版范围与后续规划

### 4.1 首版必须交付

- Windows、macOS、Linux 三平台共享核心与后台常驻能力。
- TUI、GUI、Web UI 三种可独立安装、可共存的客户端。
- 本机执行环境与 Windows WSL 执行环境。
- 第 7 节列出的首版 Agent 适配范围及公开能力矩阵。
- 工作区、会话、运行、消息、审批、提问、附件、终端、Diff 与诊断等统一领域能力。
- Coda Android 节点及其 Coding Agent 接入。
- 独立 PA 的跨端单会话、独立运行与同步。
- 设备配对、局域网直连、断连缓存、重连同步和命令幂等。
- 双向任务派发、统一通知、审批与停止。
- 按需文件与成果交接。
- 高度自主 PA 试验模式及完整行动记录。
- 必要的安全提示、日志、错误恢复、版本协商和卸载数据保护。

### 4.2 首版明确不包含

- “目标”及其边界对齐系统。
- 全量第三方历史会话导入。
- 原会话跨设备迁移。
- 持续文件夹同步。
- 可选统一配置中心的完整建设。
- SSH 远程机、普通容器环境的正式适配；协议与模型须保留扩展能力。
- 长期自动记忆提炼、无任务触发的主动闲聊等 PA 增强。
- 团队、多用户组织和复杂权限体系。

### 4.3 后续规划

1. 有限度的 Agent 安装、升级、修复与卸载；仅在能确认安装来源和所有权时自动操作。
2. 可选的统一配置、MCP、Skills 和权限规则管理；默认关闭，不覆盖原生配置。
3. SSH 远程机、更多远程执行节点和容器。
4. PA 目标系统：创建 PA 时生成初始目标，通过对齐对话确定长期目标、边界与自主程度。
5. 长期记忆、更多感知能力、更自然的主动交互。
6. 可选可信第三节点的加密存储转发，以及更丰富的异地连接方式。

## 5. 总体架构

### 5.1 架构原则

1. **执行归节点**：Agent 进程、工作区、终端、凭据和实际副作用属于运行它们的设备与执行环境。
2. **UI 是视口**：TUI、GUI、Web UI 不直接伪造任务状态，不各自保存互相冲突的会话真相。
3. **适配器隔离差异**：编排层和客户端只读取统一能力与事件，不散布 `if provider == ...`。
4. **离线可用**：每个节点拥有自己的本地数据库、PA 运行能力和本机 Agent 管理能力。
5. **主机权威**：Agent 会话和运行状态只能由所属节点推进；远端显示缓存或副本，不擅自改成完成。
6. **命令与副作用分离**：命令被接受只表示意图已持久化，不表示 Agent 已执行。
7. **能力诚实**：无法确认的能力显示未知或不支持，不以 UI 假象代替上游保证。

### 5.2 逻辑拓扑

```text
TUI ───────┐
GUI(GPUI) ─┼─ 本地版本化 RPC ─ 共享核心 A ─ Agent 适配器 ─ 本机 / WSL Agent
Web UI ────┘                    │
                                ├─ 工作区、会话、运行、终端、Diff、附件
                                ├─ PA 运行时与单会话副本
                                └─ 设备身份、同步、通知、诊断
                                          │
                            局域网加密直连 / 可选加密中继
                                          │
Android Coda ─ 移动宿主桥 ─ Coda 核心与已有能力
                                │
                                └─ PA 运行时与同一单会话副本
```

一台桌面用户的共享核心在逻辑上只有一个。WSL 是共享核心管理的执行环境，不因接入 WSL 而再安装一套产品核心。多操作系统用户的隔离属于平台安装细节，不改变单用户产品模型。

### 5.3 共享核心模块

| 模块 | 责任 |
|---|---|
| Core Runtime / Service | 生命周期、单实例、自动启动、升级与崩溃恢复 |
| Agent Registry | Agent 类型、实例、账号、版本、执行环境和能力声明 |
| Adapter Host | 原生协议、ACP、CLI / app-server 等适配器运行与隔离 |
| Workspace Service | 目录、仓库、分支、worktree、WSL 路径与环境映射 |
| Session Orchestrator | 会话、回合、排队、插话、停止、恢复和状态机 |
| Event Journal | 持久事件、序号、断点回放、投影和幂等收据 |
| Interaction Service | 权限审批、结构化提问、自由文本输入、过期与子 Agent 请求 |
| Terminal Service | PTY、输出回放、尺寸调整、重连和进程归属 |
| Change / Artifact Service | Diff、附件、生成物、校验、分块和断点续传 |
| PA Bridge | 向 PA 提供受限的设备、会话和成果操作接口 |
| Sync Service | 配对、发现、加密、增量交换、冲突合并与离线命令 |
| Notification Service | 完成、失败、提问、审批、连接变化和后台通知 |
| Diagnostics | 有界日志、版本信息、健康检查、错误分类和脱敏 |
| RPC / API Gateway | 三种 UI 与授权外部调用方共用的版本化协议 |

### 5.4 技术方向

- **GUI 采用 Rust + GPUI**，参考 Zeron 的原生客户端设计，不复制其视觉样式。
- GUI 必须是独立进程客户端；不得把会话执行、终端所有权或后台同步绑定在 GPUI 窗口生命周期上。
- 共享核心建议采用 Rust，以便复用类型、进程管理、同步和跨平台能力；最终核心语言可以在技术设计中确认，不改变本规格的外部行为。
- TUI 可复用核心类型与协议；Web UI 是薄客户端，通过同一 RPC 获取投影和事件。
- 所有界面共用版本化契约与 Mock Core，不各自解释 Agent 原始帧。

## 6. 安装、共存与后台运行

### 6.1 安装模型

用户可自由选择安装 TUI、GUI 或 Web UI 版本，也可任意组合：

- 首个界面安装时，必须自动安装并初始化共享核心。
- 后装界面必须发现、校验并复用已有核心，不得重复安装第二套核心或创建第二份用户数据。
- 核心版本不满足要求时，先执行受控升级与迁移，再让新界面连接。
- Web UI 的安装主要包含本地 Web 资产、核心托管和访问配置；不意味着必须注册云账号。
- 核心默认只为本机客户端提供受认证访问，局域网暴露必须由配对与授权流程开启。

### 6.2 后台生命周期

- 关闭窗口、退出 TUI、关闭浏览器标签或退出 GUI，均不得停止核心、Agent 会话、终端或同步。
- Windows、macOS、Linux 均必须提供用户级后台服务与自动启动能力。
- 操作系统休眠、关机或 Android 杀进程会实际中断执行，界面必须展示中断或未知状态，不能声称后台仍在运行。
- 核心异常退出后应有有界退避重启；不得无限快速重启或未经核对重复执行副作用不明的命令。
- 核心升级不得无声终止正在运行的 Agent；应等待安全点或明确提示影响。
- 关闭某个终端视图不等于关闭 PTY；停止 Agent 回合也不等于删除会话。

### 6.3 卸载与数据

- 卸载一个 UI 不删除其他 UI、核心、会话或附件。
- 卸载核心前必须列出仍在运行的任务，要求明确确认，并提供保留数据的默认选项。
- 删除会话、撤销设备、停止核心和停止某个 Agent 必须是不同操作，文案不得混淆。

## 7. Agent 首版适配范围

### 7.1 用户明确点名的范围

| Agent / 平台 | 首版要求 | 说明 |
|---|---|---|
| Claude Code | 专项适配 | 优先支持官方 CLI 控制协议、会话恢复、提问与权限等 |
| Codex | 专项适配 | 优先支持官方 app-server / JSON-RPC，而非仅一次性 CLI 输出 |
| DeepSeek Harness | 专项适配 | 验证其插件、会话、工具和控制接口，固定兼容版本 |
| Qoder | 专项适配 | 区分原生 Agent 会话接入与 Coda 已有模型渠道接入 |
| TRAE | 专项适配 | 区分 TRAE Agent / SOLO 能力与 OAuth 模型渠道 |
| WorkBuddy（wb） | 专项适配 | 复用已有接入经验，明确国内与国际产品差异 |
| CodeBuddy（cb） | 专项适配 | 覆盖国内版与国际版的适用入口，不能只把网关当成会话协议 |
| Cursor | 专项适配 | 用户前文“Corser”按 Cursor 理解；使用其可用 Agent / CLI 接口 |
| Antigravity（反重力） | 专项或通用协议加差异适配 | 注意账号隔离、安装来源与原生权限差异 |
| Grok Build | 专项或通用协议加差异适配 | 验证登录、模型、审批和运行控制 |
| Coda Coding Agent | 移动节点专用适配器 | 作为已有 Android 执行能力接入，不属于桌面第三方 Agent |

### 7.2 其他热门 Agent 的首版扩展覆盖

为避免首版只适配少数产品，适配器体系还须覆盖下列热门或参考项目已验证存在的 Agent。可以通过通用 ACP、官方 RPC / app-server、CLI 控制协议或专用适配器实现：

- OpenCode
- Gemini CLI
- GitHub Copilot 的可编程 Agent 入口
- Kiro CLI
- Pi Coding Agent
- Hermes Agent
- OpenClaw 的可编程入口
- Kimi CLI / Kimi Code 的可用 Agent 入口
- fx
- 其他进入 ACP Registry 或提供兼容协议的 Agent，应尽可能通过通用适配器直接获得基础支持

“Devin”等主要由云端拥有运行时和工作区的产品，不自动套用本地 CLI 模型；其 API、工作区归属和控制能力需另行验证，不能仅为凑齐名单宣称本地适配。

### 7.3 适配完成定义

一个 Agent 只有满足以下条件，才能在发布能力矩阵中标记“已支持”：

1. 固定并记录受支持版本、安装发现方式与执行环境。
2. 能复用原账号或提供明确登录路径，不静默串用其他账号。
3. 能在指定工作区创建会话并持久保存供应方会话引用。
4. 能恢复由本产品创建的会话，或返回可诊断的恢复失败。
5. 能发送任务、接收标准化事件、停止并正确结算回合。
6. 对公开的模型、插话、审批、提问、附件、子 Agent、Diff 等能力逐项验证。
7. 通过通用回放场景与该 Agent 的真实接口冒烟测试。
8. 所有不支持或降级的项目都在 UI 和能力矩阵中可见。

仅能启动一个 TUI、只解析一次文本输出或只接入模型 API，不得标记为完整 Agent 适配。

## 8. 统一 Agent 能力模型

### 8.1 能力声明

每个“Agent 实例 × 版本 × 执行环境”在会话建立时生成带版本的能力声明，至少包括：

- 会话：多供应方线程、模型切换、权限模式切换、恢复与请求持久性。
- 线程：空会话、快照、派生、从指定回合派生、原生线程 ID。
- 回合：开始/结束事件、停止、原生插话、停止后插话、排队、终态可信度。
- 流式内容：正文、推理、工具输出、计划文本、消息完成事件。
- 工具：工具 ID、开始/结束、输出、MCP、动态工具回调。
- 审批：命令、文件读取、文件修改、Patch、子 Agent 请求和原生请求 ID。
- 计划：Todo、结构化计划、可执行计划、结构化提问。
- 子 Agent：生命周期、独立线程、等待、关闭和派生。
- 上下文：系统/开发者上下文、摘要、完整或增量交接。
- 检查点：文件系统快照、会话回滚及两者是否一致。
- 身份关联：线程、回合、条目和请求 ID 的强度。
- 附件与成果：输入格式、大小限制、生成物和读取方式。

能力声明是运行期事实，不是只按产品名称写死的全局布尔值。

### 8.2 基础能力与适配策略

| 统一能力 | 原生路径 | 无原生能力时的适配路径 | 不得出现的行为 |
|---|---|---|---|
| 排队消息 | 上游队列 | 核心持久队列，在当前回合安全结束后发送 | 丢消息、换序或重复发送 |
| 运行中插话 | 原生 steer / 控制协议 | 停止当前回合，保存部分输出与上下文，恢复原会话并追加新指令 | 静默创建无上下文的空会话 |
| 停止 | 原生 interrupt | 受控停止进程/会话并核对终态 | 仅把 UI 改成已停止 |
| 会话恢复 | 原生 resume / thread cursor | 使用保存的原生引用和适配器恢复流程 | 恢复失败仍显示为正常续聊 |
| 会话派生 | 原生 fork | 在同一工作区创建带应用摘要的新会话 | 声称原生分支已复制 |
| 模型切换 | 原生 set model | 新供应方线程并交接必要上下文 | 把“default”当真实模型名发送 |
| 文件检查点 | 应用侧 Git / 文件快照 | 只恢复文件并标明会话上下文分歧 | 文件恢复后声称会话也已回滚 |
| 审批 | 原生请求与回调 | 使用上游沙箱/策略；没有请求就不伪造审批 | 以宿主 UI 代替上游权限强制 |
| 计划与 Todo | 结构化事件 | 展示普通文本，不创建假结构化数据 | 把任意文本伪装成计划对象 |
| 子 Agent | 原生生命周期 | 展示能获取的嵌套事件或摘要 | 父回合结束即丢弃仍在运行的子任务 |
| Diff | 原生差异 | 从所属工作区计算 Git Diff | 用另一设备的路径或凭据计算 |
| 附件 | 原生多模态/文件输入 | 转为上游支持的文件或文本引用 | 认为提示词中的路径本身已授权访问 |

### 8.3 插话适配的强制语义

“停止 → 恢复 → 追加消息”是首版明确要求的适配策略，必须满足：

1. 记录原会话 ID、原回合 ID、适配策略和新消息 ID。
2. 保留已产生的部分回答、工具事件及停止原因。
3. 新指令只持久化一次；网络重试不得再生成一个用户消息。
4. 停止不撤销已经发生的文件、命令或网络副作用，必要时提示用户。
5. 停止后等待上游可恢复的安全点；不能一边旧回合仍运行一边假装插话成功。
6. 恢复原会话失败时返回明确错误，不得静默在新会话中重放任务。
7. 因停止而过期的审批和提问必须关闭或标记失效，不能将答案发给新回合的旧请求。
8. UI 可统一称为“插话”，但会话详情与诊断中必须能区分原生插话和替换回合适配。

### 8.4 上下文交接不等于跨端迁移

在同一执行环境内，为了模型或 Agent 切换，可以通过摘要和上下文交接创建新会话。该能力不承诺把原会话完整执行状态迁移到另一台设备；跨设备仍只做远程管理、信息同步与成果交接。

## 9. 产品功能规格

### 9.1 设备与执行环境

- 展示本机及已配对的 Coda / 桌面节点。
- 节点状态至少包括在线、离线、休眠未知、同步中、版本不兼容、未授权。
- 执行环境至少包括桌面宿主机与 Windows 的指定 WSL 发行版。
- 工作区唯一身份由“所属节点 + 执行环境 + 规范化路径”构成，不以另一台设备上相同路径推断为同一目录。
- 远程操作失败不能自动回退到本地同名目录或本地账号执行。

### 9.2 Agent 与账号

- 扫描已安装 Agent、可执行文件、版本和适用环境。
- 状态检查不得意外启动会话、MCP、Hooks 或登录浏览器。
- 默认复用 Agent 自己的认证、订阅和原生配置。
- 多账号实例必须隔离会话、模型目录和凭据，不得继承未配置的 ambient credentials。
- 登录未知状态显示“未知”，不能仅凭模型列表缓存判断已登录。
- 首版只提供必要的诊断与跳转，不以安装、更新和卸载管理为核心。

### 9.3 工作区与项目

- 添加本地目录、Git 仓库和 WSL 目录。
- 读取分支与仓库状态；支持时创建隔离 worktree。
- 项目设置属于所属执行环境，不因另一设备连接而自动复制。
- 路径、符号链接、WSL 与 Windows 路径转换必须由所属节点校验。
- 不在首版提供持续文件同步；文件访问围绕具体任务、会话和成果进行。

### 9.4 会话管理

- 创建、恢复本产品创建的会话，重命名、归档、删除、标记未读/已读。
- 会话列表显示所属节点、环境、工作区、Agent、模型、最近活动和真实状态。
- 支持多 Agent 会话并行，用户可绕过 PA 直接使用。
- 不统一导入第三方全部历史；仅管理本产品创建或用户明确接入的会话。
- 会话状态至少包括：草稿、排队、运行、等待用户、部分失败、受限/限额、已完成、已停止、失败、离线未知、归档。

### 9.5 消息与运行

- 正文、推理、工具调用、命令输出、文件修改、计划、错误和附件按统一事件模型呈现。
- 支持流式增量、断点回放和重连恢复，不要求每次重新拉取全部历史。
- 发送失败时保留草稿和附件，不静默清空输入。
- 支持消息排队、原生或适配插话、停止和失败重试。
- 所有重试使用相同逻辑命令/消息 ID，防止重复创建。
- 回合结束、后台命令结束和子 Agent 结束可以是不同里程碑，不得混为一谈。

### 9.6 模型与运行选项

- 按适配器实际返回展示模型、推理档位、上下文和速度/服务选项。
- 不支持的选项不显示，或解释降级，不生成无效请求。
- 会话恢复后重新核对当前可用模型与权限模式，不能盲用旧缓存。
- 第三方模型配置默认仍归第三方 Agent；Coda 已有供应商与 OAuth 能力可以复用实现经验，但不默认跨端同步密钥。

### 9.7 提问与审批

- 支持单选、多选、自由文本、分页问题和权限选项。
- 保留上游原生选项 ID，不以显示文案猜测有效答案。
- 审批可以来自主 Agent 或子 Agent，需显示真实来源、工具、参数摘要与所属会话。
- 请求在核心重启后尽可能恢复；上游不支持恢复时明确标为不可继续。
- 多端看到同一请求时，只有一个有效处理结果；其他端更新为已处理、过期或结果未知。
- PA 高度自主模式下可以自动批准或拒绝，但必须记录决定者、依据和结果；用户直接操作时同样记录。

### 9.8 终端

- 终端在所属执行环境中运行，支持创建、输入、输出、调整大小、分离、重连和关闭。
- UI 退出不关闭终端；提供有界输出回放，避免无限内存增长。
- 远程终端操作必须经过目标节点授权，不能把按键流落到同名本地终端。
- 首版至少满足日常任务检查与简单交互；TUI/GUI/Web 可采用不同渲染实现。

### 9.9 Diff、附件与成果

- 展示变更文件、增删统计、文本 Diff 和适用时的未跟踪文件。
- 支持图片、文件等输入附件及 Agent 生成物。
- 文件与成果按需交接，支持分块、SHA-256 校验、暂停/断点续传和失败重试。
- 大文件或超大 Diff 不应完整塞入消息日志；使用带元数据的 Artifact 引用。
- 成果下载必须来自实际所属节点；节点离线时显示不可用或已缓存，不创建空文件。
- 不进行全工作区镜像，也不将 `.git` 或任意主机路径当成默认可下载资源。

### 9.10 通知与诊断

- 完成、失败、等待提问、等待审批、配额受限、设备离线和连接恢复均可通知。
- 后台通知由核心产生，因此 UI 关闭后仍有效；移动通知受 Android 系统能力约束。
- 错误至少区分：未安装、版本不兼容、未认证、配额/限流、模型不可用、权限拒绝、进程退出、协议错误、网络断开、工作区失效和上游未知错误。
- 诊断日志必须有界、脱敏，不能默认记录完整密钥、附件内容或所有工具输入。
- 提供适配器版本、能力矩阵、会话引用和必要原始协议摘要，便于排查不同 Agent 的差异。

## 10. Personal Agent 规格

### 10.1 身份与独立性

- PA 是个人助理，以较拟人化方式与用户交流，帮助协调会话并主动跟进工作。
- PA 独立于 Coding Agent，不复用其会话内核、个人资料或陪伴状态。
- PA 使用单用户、单会话模型；桌面与 Android 呈现的是**同一身份、同一连续会话**，不是每端各建一条 PA 对话。
- 各端都拥有可独立运行的 PA 实例，另一端离线不妨碍本端 PA 工作。

### 10.2 PA 与 Agent 会话的关系

- PA 对话通常与具体 Agent 对话无关，不以 Agent 会话为中心组织。
- 不在 PA 会话中强制生成任务卡片，也不要求通过卡片式关联展示所有 Agent 工作。
- PA 可以在后台调用受控能力协调、检查、停止或跟进 Agent。
- Agent 的工具过程、消息与管理界面保留在 Agent 会话中，不复制成 PA 的第二条完整会话。
- 用户可以直接管理 Agent，不强制先经过 PA。

### 10.3 首版高度自主试验模式

- 创建或启用时必须明确告知：PA 可自主选择 Agent、创建会话、发送任务、跟进结果并处理审批，属于试验性能力。
- 首版不提供额外的自主程度切换，也不设置专门的 PA 暂停开关。
- 所有自主操作必须可审计：时间、发起节点、目标、参数摘要、结果、失败和决定者。
- 高度自主不等于可以绕过设备配对、目标节点授权或上游真实权限机制。
- 用户可以停止具体 Agent 回合、停止核心或撤销设备授权；这些通用安全操作不属于额外的 PA 自主模式开关。

### 10.4 PA 单会话跨端规则

- 每条用户消息和 PA 回复具有全局唯一 ID、来源节点和逻辑时间信息。
- 允许两端同时发送，不通过锁定另一端输入来规避问题。
- 并发消息全部保留，按确定性规则合并展示；PA 回复应携带 `reply_to` 或等效来源信息，避免语境错配。
- 两端分别产生的 PA 回复可以都保留；同一后台命令仍由命令 ID 去重，不因双端运行而重复执行。
- 消息以追加为主，首版不做复杂的多端消息正文协同编辑。
- PA 的人设、个人资料、规划/回复模型选择和单会话记录纳入同步；API Key 等秘密默认留在原节点。
- 长期自动记忆提炼和“目标”不属于首版，不得以空开关占位。

## 11. 跨端同步与远程控制

### 11.1 同步模型

采用**设备自治、局域网优先、无强制中心服务**的分布式模型：

- 每台设备保存本地权威数据、PA 副本、同步游标和待发送操作。
- 同一局域网自动发现候选设备，经用户配对后建立加密连接。
- 设备在线时实时交换增量；断连后本地继续，重连后按游标补交与合并。
- 可使用版本向量/等效游标、操作日志、快照和适合的数据结构实现收敛；禁止用整个数据库的最后写入覆盖解决冲突。
- PA 消息可采用追加日志或适用 CRDT；运行和命令采用明确的所有权与状态机，不能仅靠通用 LWW。
- 可借鉴 Syncthing 的发现、直连和重连思想，但不复用其文件夹同步产品模型。

### 11.2 分布式送达的真实边界

- 一端离线时，另一端能够继续聊天、规划和执行本机任务。
- 发给离线节点的远程命令保存在待同步队列中，状态为“等待目标在线”。
- 只有目标节点确认后，才能显示已接收、已停止、已批准或已执行。
- 如果设备从未再次同时在线，且没有其他可信在线节点保存副本，则消息和命令无法保证送达。
- 可选内网穿透、虚拟组网或加密中继只增强连接，不把核心变成必须依赖官方消息云的产品。
- 中继若存在，只转发端到端加密数据；不是默认可读的消息数据库。

### 11.3 配对与连接

- 支持二维码/短码/链接配对，并在设备上确认身份指纹。
- 每台设备拥有独立长期身份密钥和可撤销授权。
- 局域网发现不等于自动信任；仅凭知道 IP 或配对页可访问不得获得管理权限。
- 支持手动地址，处理 mDNS/广播不可用、网络切换和地址变化。
- Web UI 默认本机访问；远程 Web 访问必须通过明确授权的加密通道，不直接暴露无认证 HTTP 管理面。
- 撤销设备后拒绝后续连接和命令，但不因此伪造远端 Agent 已停止。

### 11.4 同步数据范围

| 数据 | 同步策略 | 权威来源 |
|---|---|---|
| PA 身份、人设、个人资料 | 跨端合并 | 明确字段策略与用户操作 |
| PA 单会话消息 | 全量增量复制，断连合并 | 各来源节点追加，确定性收敛 |
| 设备与环境目录 | 同步 | 各设备自己的记录 |
| Agent 会话元数据 | 同步 | 会话所属节点 |
| Agent 完整消息/事件 | 在线时持续同步最近窗口与活跃会话；打开会话时补取所需历史，形成本地副本 | 会话所属节点 |
| 运行与回合状态 | 同步投影 | 实际执行节点 |
| 管理命令 | 持久排队、幂等投递 | 发起节点写意图，目标节点写结果 |
| 审批与提问 | 同步请求和处理结果 | 实际执行节点 |
| 未读与通知 | 同步必要的领域状态 | 按会话/用户操作合并 |
| 文件与成果 | 按需传输和缓存 | 工作区/成果所属节点 |
| Agent 凭据、API Key、OAuth Token | 默认不同步 | 原节点安全存储 |
| 原生 Agent 配置 | 默认不统一 | 各 Agent / 节点 |
| UI 窗口位置、尺寸、打开标签和快捷键 | 不同步 | 当前客户端 |

### 11.5 命令幂等与结果不确定

- 命令包含 `command_id`、来源节点、目标会话、类型、基于的状态、创建时间和过期策略。
- 同一 `command_id` 的重复投递只处理一次，目标节点持久保存处理收据。
- 命令状态至少包括：本地已保存、等待目标、已送达、已接受、执行中、成功、拒绝、过期、被取代、结果未知。
- 如果核心在外部副作用发生后、结果提交前崩溃，不得盲目再次执行；恢复时应查询 Agent/会话状态并标记“结果未知”或完成核对。
- 对非幂等外部操作，不承诺仅凭重试就能实现数学意义上的“恰好一次”；必须通过上游 ID、状态核对和人工可见记录避免重复。
- 新的停止/插话命令可以使尚未执行的旧命令失效，但不能撤销已发生的副作用。

### 11.6 远程会话与离线缓存

- 在线时，远端 UI 通过目标节点获得实时事件、审批、终端和成果。
- 在线连接期间，核心应同步会话列表、最近消息窗口和活跃会话的必要事件；用户打开较旧会话时按需补取历史，不预先复制第三方设备的全部历史库。
- 离线时可以阅读已同步内容并创建待发送命令，但必须显示最后更新时间和离线状态；尚未同步的旧消息或成果明确显示“需要原节点在线”，不以空白代替。
- 已打开过且完成同步的会话，在节点离线后仍应能回看已有消息，而不仅是看到一行会话标题。
- 离线副本不能被误认为实时会话，也不能从其他设备本地路径推导工作区状态。
- 首版不迁移会话宿主；重连后仍由原所属节点继续执行。

## 12. 三种界面与交互要求

### 12.1 共同信息架构

三种界面共享以下领域入口，具体布局可不同：

1. 设备与执行环境。
2. 工作区与项目。
3. Agent 会话与运行状态。
4. 新建任务与会话设置。
5. 审批、提问与通知。
6. Diff、附件和成果。
7. 终端。
8. 独立 PA 单会话。
9. Agent、账号、配对、同步和诊断设置。

### 12.2 GUI（GPUI）

重点参考 Zeron 的桌面交互质量：

- 虚拟化长会话列表，流式输出不反复重建全部消息。
- 稳定的跟随底部行为；用户向上翻阅时不被新消息强制拉回。
- Markdown、代码高亮、工具调用分组、提问面板、附件和错误呈现。
- 可调整会话侧栏、Diff 区和终端区；布局属于本机 UI 偏好。
- 草稿按会话保存，发送失败可恢复。
- 后台通知、重连不丢当前页面状态。
- 完整键盘操作、IME 输入、减少动态效果选项和可读对比度。

这些是体验方向，不要求复刻 Zeron 的颜色、尺寸、动画时长或品牌。

### 12.3 TUI

- 使用与 GUI 相同的核心 RPC 和会话投影，不另写一套 Agent 控制逻辑。
- 支持会话浏览、发送、排队/插话、停止、审批、提问、模型选择和状态查看。
- Diff、终端和附件以终端可表达的方式呈现；图形能力不足时提供保存或外部打开。
- 远程会话的交互结果必须来自核心，不直接在本机误启动同名 Agent。

### 12.4 Web UI

- 由核心本地承载或作为已安装客户端连接核心，不依赖官方云网页。
- 与 TUI/GUI 共用协议、能力和权限，不保存第二份权威任务数据库。
- 浏览器刷新或关闭不影响 Agent 与终端。
- 明文局域网 HTTP 不自动获得敏感管理权限；远程访问采用配对和加密连接。

### 12.5 窗口同步的含义

同步的是 PA 对话、Agent 会话与列表、运行状态、未读、通知、审批和管理操作；**不同步**原生窗口的位置、尺寸、当前选中页面、打开的标签布局和客户端快捷键。

## 13. 核心领域对象与协议要求

### 13.1 主要对象

| 对象 | 关键内容 |
|---|---|
| Device | 设备 ID、名称、平台、公钥、在线状态、授权与版本 |
| ExecutionEnvironment | 宿主机、WSL 发行版，未来可扩展 SSH / 容器 |
| AgentDefinition | Agent 类型、适配器类型、协议与展示信息 |
| AgentInstance | 安装、版本、账号实例、环境、能力和健康状态 |
| Workspace | 所属节点、环境、规范化路径、仓库与 checkout 身份 |
| Session | 供应方线程引用、工作区、Agent、模型、配置、状态与时间 |
| Run / Turn | 一次逻辑任务与实际上游回合、替换回合关系、终态 |
| Event | 有序消息、推理、工具、计划、错误、子 Agent 等事件 |
| InteractionRequest | 审批/提问、原生请求 ID、来源执行节点、状态与答案 |
| Command | 全局 ID、来源、目标、参数、状态、收据和过期/取代关系 |
| Artifact | 内容哈希、类型、大小、所属节点、元数据和缓存位置 |
| PAProfile / PAMessage | PA 身份与单会话追加消息 |
| SyncCursor | 各对端的数据进度、快照版本和待确认操作 |

### 13.2 RPC 类别

- UI RPC：会话列表、投影订阅、消息回放、草稿展示数据、设置和本地状态。
- Control RPC：创建/发送/插话/停止、审批回答、终端、模型和工作区操作。
- Sync RPC：设备目录、增量交换、游标、快照、命令投递和回执。
- Artifact RPC：上传、下载、分块、哈希、断点和元数据。
- PA RPC：单会话读写、PA 本地运行、受控协调能力与行动记录。
- Diagnostics RPC：版本、能力、健康和脱敏日志。

### 13.3 协议约束

- 所有 RPC 具有协议版本、能力协商和向后兼容策略。
- 订阅采用“快照 + 有序事件”或等效模型，支持断点续传和缺口检测。
- 事件日志、投影更新和命令收据必须有一致的事务边界。
- 外部 I/O 在持久化意图后执行，结果再写回；不能把数据库提交成功当成 Agent 已完成。
- UI 不接收无界的全量原始日志；日志、Diff 和附件均需要限制与分页。
- 外部 Agent 若通过 MCP/API 接入核心，必须单独授权范围，不能因 socket 已认证就自动获得全部权限。

## 14. 安全、隐私与信任边界

### 14.1 默认保留原生边界

- Agent 的账号、订阅、原生权限和沙箱仍由 Agent 自己负责。
- 统一 UI 的权限提示不能替代上游真实强制执行。
- 不因方便适配而默认关闭 Hooks、Skills、CLAUDE.md、项目说明或原生安全配置。
- 远程客户端不得把自己的文件系统、凭据或机器状态代入目标执行环境。

### 14.2 高度自主风险提示

首次启用 PA 时必须清晰说明其可能：

- 创建和控制 Agent 会话；
- 自动处理命令与文件修改审批；
- 通过 Agent 安装依赖、修改文件、执行命令或进行其他受支持操作；
- 在已配对设备之间发起远程操作。

首版以高度自主为产品选择，不能用“实验性”文案替代审计、授权和真实状态呈现。

### 14.3 秘密与内容保护

- 凭据优先保存在各平台安全存储中，日志和同步消息默认脱敏。
- 配对码、授权 URL、Token 和密钥不得出现在普通诊断导出中。
- 文件访问必须校验工作区包含关系、符号链接和授权范围；提示词里写路径不等于授权读取。
- 远程附件按哈希、大小和类型验证，临时文件完成后原子提交。
- 同步复制工具内容时，可减少完整 Write/Edit 内容等敏感负载；完整内容留在所属节点的有界日志中。

### 14.4 远程授权

- 设备配对、Web 客户端、PA 和外部 Agent 调用分别具有可识别身份。
- 读取会话、控制会话、终端操作、文件访问、设备管理和核心维护应是可区分的权限。
- 撤销授权立即影响新请求；无法确认的远端执行结果显示未知，不伪造已撤销副作用。

## 15. 可靠性与非功能要求

### 15.1 可靠性

- 核心崩溃后能够恢复会话目录、事件投影、待处理命令和连接状态。
- 进程退出与 Agent 正常结束严格区分。
- 重启后不能把未确认回合直接标为成功；应恢复、核对或标记中断/未知。
- 所有队列、附件和终端回放有容量限制及清理策略。
- Agent 版本升级后重新探测协议与能力，不能沿用不兼容缓存。

### 15.2 性能目标

以下为验收目标，需在确定的基准设备上量化：

- 本地 UI 与核心交互在正常负载下应保持即时反馈；长任务不能阻塞 UI 线程。
- 流式事件只更新受影响的会话区块，长列表使用虚拟化或分页。
- 局域网在线时，元数据和普通控制事件应在秒级内可见；大文件传输不得阻塞控制通道。
- 冷启动优先展示最近本地投影，再后台校对远端状态。
- GPUI 的 Markdown、Diff、语法高亮和终端解析不得随流式输出反复执行全量计算。
- 核心在 UI 全部关闭后仍保持低空闲资源占用，不为每个界面各启动一套 Agent 进程。

### 15.3 可维护性

- 新 Agent 原则上只新增定义、适配器、能力声明、测试和文档，不修改所有 UI。
- 通用 ACP 适配器中不得堆叠特定 Agent 条件；差异通过独立 flavor/策略扩展。
- 所有适配器使用真实上游录制帧建立回放测试，而非只用手写理想帧。
- 协议、数据库和同步数据都必须带 schema 版本与迁移测试。

## 16. 测试与首版验收

### 16.1 适配器通用测试

每种声明支持的 Agent 按能力运行适用场景：

1. 简单单回合、多回合与流式输出。
2. 消息排队、运行中插话、停止后恢复插话。
3. 发送后立即停止、回合尚未注册时停止。
4. 会话恢复、核心重启后恢复、上游会话丢失。
5. 命令审批、文件修改审批、结构化提问和自由文本回答。
6. 工具调用、子 Agent、后台工作和父回合先结束的情况。
7. 模型切换、推理选项、权限模式和真实降级。
8. 配额受限、认证过期、进程崩溃、输出中断与协议未知字段。
9. 附件输入、生成物、Diff 和大输出截断。
10. 真实二进制的受控冒烟测试与录制协议回放测试。

### 16.2 三界面与安装验收

- 在三个桌面平台分别安装任一 UI，核心自动安装并可后台运行。
- 安装第二种、第三种 UI 后核心数量、数据目录和任务集合不变。
- GUI/TUI/Web UI 对同一 Mock Core 的契约测试结果一致。
- 关闭所有 UI，Agent、终端、通知和同步继续；重新打开可恢复视图。
- 核心或 UI 版本不一致时给出明确升级/降级提示，不静默破坏数据。

### 16.3 WSL 验收

- Windows 核心能发现并使用指定 WSL 发行版中的 Agent。
- WSL 工作区、路径、终端、Git Diff、附件和会话恢复均使用 Linux 环境事实。
- Windows 与 WSL 中存在同名 Agent 或相同路径文本时不串用。
- WSL 停止或不可用后，相关任务显示环境离线/失败，不回退到 Windows 同名目录执行。

### 16.4 跨端验收场景

**场景 A：双向控制**
手机控制电脑 Agent，电脑控制 Coda Coding Agent；两边均能看到真实状态并处理各自获授权的操作。

**场景 B：一端离线**
电脑关机后，手机 PA 和手机本机 Agent 继续可用；电脑会话显示最后已知状态。手机发出的停止命令只显示等待，不显示成功。

**场景 C：PA 单会话合并**
两端在断连时分别发送消息并产生回复，重连后消息全部保留、顺序确定、回复来源清楚，不形成两条独立 PA 会话。

**场景 D：命令去重**
同一命令因断网、重连或双端运行被重复投递，目标节点利用命令 ID 和状态核对避免重复创建会话或重复回答审批。

**场景 E：审批竞争**
两端同时处理同一审批，只有一个结果被上游接受，其他端显示最终状态；过期请求不能误答到新回合。

**场景 F：插话适配**
对不支持原生插话的 Agent，旧回合确实停止，部分输出保留，新消息在原会话中恢复发送；恢复失败不得伪装成功。

**场景 G：成果交接**
大附件分块传输，中途断网后续传，哈希一致；不触发工作区其他文件同步。

**场景 H：授权撤销**
撤销设备后无法继续读取或控制节点，已缓存数据按产品策略处理，且不会把远端任务状态伪造为停止。

### 16.5 发布门槛

- 所有首版 Agent 均有公开的能力矩阵、支持版本和限制说明。
- 标记“已支持”的适配器通过其声明能力的测试；通用协议覆盖也必须有真实样例验证。
- 不允许用“能跑通一次任务”替代完整验收。
- 三平台后台生命周期、WSL、Coda 双向控制、PA 单会话和局域网断连恢复均通过核心场景。
- 高度自主 PA 的行动日志、审批记录和风险提示可检查。

## 17. 推荐实施顺序（不改变首版范围）

1. **M0：领域协议与核心骨架**
   确定 Device / Environment / Workspace / Session / Run / Command 模型、RPC、事件日志、Mock Adapter 和数据库。

   Android 节点桥、双向控制、PA 单会话同步、局域网配对、离线命令和通知。
6. **M5：成果、可靠性与安全收尾**
   按需附件、断点续传、恢复核对、权限撤销、诊断、性能与全量验收。

## 20. 已对齐的关键决策摘要

1. 桌面端管理已有 Agent，不另造通用 Agent；Coda Coding Agent 是已有的移动节点能力。
2. 提供统一会话与工作台，用户可绕过 PA 直接使用 Agent。
3. 三平台、三界面、一个共享核心，界面可独立安装并共存。
4. 关闭任何 UI 后核心持续运行，GUI 使用 GPUI 方向。
5. 首版主要打通 WSL，不排除未来 SSH 和容器。
6. 适配范围不止 Claude Code、Codex、DeepSeek Harness，还覆盖 Qoder、TRAE、WorkBuddy、CodeBuddy、Cursor、Antigravity、Grok Build 及其他热门 Agent。
7. 完整适配以真实工作流、能力矩阵和测试为准，不以四项基本操作或模型 API 接入为完成标准。
8. 无原生插话时，通过停止当前回合、恢复原会话、追加新指令补齐；全过程保留真实状态。
9. PA 是独立、连续的单会话个人助理，与 Agent 会话不做强制卡片式关联。
10. PA 两端可独立运行、允许同时发消息并同步；后台操作以命令幂等和宿主所有权防止重复。
11. 首版 PA 使用高度自主试验模式，可处理审批，不增加自主程度切换或 PA 暂停开关。
12. “目标”属于未来功能，首版不纳入。
13. 局域网优先、设备自治、无强制中心服务；离线命令等待重连，不伪造成功。
14. 不做原会话跨端迁移，不做持续文件夹同步；按需文件与成果交接保留。
15. 不统一导入历史，不默认统一配置；可选配置中心和有限安装维护属于后续规划。

## 21. 文档评审时建议重点检查

为避免实现阶段再次混淆，评审时应优先确认以下表述，而不是继续扩大功能名单：

- 第 7 节的 Agent 名称是否与实际产品入口一一对应，尤其是国内/国际版与云端 Agent。
- 第 8 节的能力与降级是否符合期望，特别是插话、回滚、审批和子 Agent。
- 第 10 节是否准确表达“PA 独立单会话、不做卡片式关联”。
- 第 11 节是否接受无中心服务时的真实送达边界。
- 第 16 节发布门槛是否符合首版范围；任何缩减都应显式修改版本定义，而不是以“部分适配”替代验收。
