# Coda 跨端 Agent 控制与协同平台：规格文档集

本目录是桌面端与跨端协同特性的需求、验收和实施任务基线。

## 文档

| 文档 | 作用 | 是否可作为发布依据 |
|---|---|---|
| [SPEC.md](./SPEC.md) | 产品边界、领域模型、功能与架构约束 | 产品行为以本文为准 |
| [ACCEPTANCE.md](./ACCEPTANCE.md) | 可执行验收标准、测试矩阵、发布门槛 | 是 |
| [TODO.md](./TODO.md) | 可认领任务、依赖、产出物、验收映射 | 实现进度以本文为准 |
| [SUPPORT-MATRIX.md](./SUPPORT-MATRIX.md) | 各 Agent 的支持版本、能力、证据和发布状态 | 是；没有证据不得标为 Supported |

## 阅读顺序

1. 先读 `SPEC.md` 的定位、范围、架构原则、PA 单会话规则和同步边界。
2. 实现前读 `ACCEPTANCE.md` 的验收等级、环境规范与对应模块。
3. 在 `TODO.md` 中认领任务；每项任务必须填写对应验收编号与验证证据。

## 状态定义

- **SPEC**：描述应该做什么，不因当前代码难实现而降低要求。
- **ACCEPTANCE**：描述如何证明做到；证据必须可复现。
- **TODO**：描述下一步做什么；任务完成不等于验收通过。
- **PASS / FAIL / BLOCKED / NOT RUN**：验收状态；`BLOCKED` 和 `NOT RUN` 不得计作通过。
- **Supported / Experimental / Unavailable**：Agent 能力状态；只有经过对应验收的项可标为 Supported。

## 变更规则

1. 新功能先修改 SPEC，再补验收编号和任务。
2. 任何范围缩减必须明确写进 SPEC 的版本记录，并在 TODO 中标注影响，不得用“部分实现”默认替代。
3. Agent 适配完成必须同时更新其能力矩阵、测试证据和支持版本；不得只更新任务状态。
4. 测试不得使用真实用户凭据或生产工作区。录制协议数据必须脱敏。
5. 验收证据按 `artifacts/acceptance/<run-id>/` 归档，至少保存命令、环境、结果和失败日志。
6. 提交文档和实现时只引用本目录稳定 ID，不用章节号充当唯一验收 ID。
